# Этап 1: исследование Babylon.js, толщина и концепция интерфейса

Статус: проектное предложение, 28 октября 2026. Это исследование документации и проектирование интерфейса; прототип, пользовательские тесты и сравнение производительности ещё не проведены. Инструкция о сложности Babylon Node Material Editor — наблюдение владельца проекта; приведённые ниже решения — гипотезы, а не доказанная оценка удобства. Документ уточняет [основное исследование](research-stage-1.md).

## Цель и принципы

Человек без знаний WebGL должен создать материал, увидеть его на объёмном листе, настроить стороны и торцы, добавить эффекты и сохранить результат. При этом опытному пользователю нужны слои, маски и доступ к сложным возможностям. **Удобство интерфейса — один из критериев готовности первого этапа**, а не последующая косметическая работа.

1. Начинать с результата и задачи («Бумага», «Добавить пятно»), а не с GPU, шейдерных стадий или структуры узлов.
2. На экране всегда ясно, что выбрано, к какой стороне и области относится изменение и как его отменить.
3. Простые настройки доступны сразу; дополнительные раскрываются рядом с соответствующим объектом. Скрытые параметры остаются сохранёнными, их изменения отмечены индикатором.
4. У каждого сложного действия есть предпросмотр, понятное значение по умолчанию, сброс только выбранной настройки и отмена.
5. Один источник состояния проекта для всех режимов: переход на граф и обратно не должен молча изменять результат или терять информацию.

## Толщина и торцы — обязательное требование P0

### Поведение

- Один прямоугольный объект с шириной, высотой и неотрицательной толщиной. Предлагаемые единицы в UI — мм; при создании проекта устанавливается единый масштаб, а размеры сохраняются как абсолютные значения в этих единицах. Допустимые диапазоны, числовая точность и значения по умолчанию уточняются после проверки масштаба сцены и камеры. Толщина не зависит от приближения камеры и не должна автоматически менять ширину/высоту.
- Толщина 0 — плоский лист с двумя сторонами; положительное значение — геометрия с четырьмя реальными торцевыми гранями. Переключение через 0 сохраняет выбранные настройки обеих сторон и торцов; при нуле настройки торцов видимы, но помечены как не отображающиеся. Показать фокус/быстрый вид сбоку, чтобы тонкий торец было реально увидеть.
- Лицевая, обратная сторона и «Торцы» — три области выбора. По умолчанию четыре торца используют один общий редактируемый материал. Предусмотреть P1 отдельные настройки каждого из четырёх торцов, но независимые цвета/текстуры на двух основных сторонах и общий материал торцов — P0.
- Для торца: в P0 цвет, базовая текстура, материал/шероховатость и эффекты из доступного каталога с масками. По умолчанию цвет торца согласован с выбранным бумажным пресетом; при самостоятельном редактировании пользователь видит, что связь отключена. P1: импорт и настройка normal map торца и независимые материалы четырёх граней.
- Различать **эффект на торце** и **эффект у края поверхности**. Первое касается новых четырёх граней, второе — маска на лицевой/обратной поверхности. В выборе области эффекта доступны обе формулировки и подсветка результата в viewport.
- Создание толщины не включает bevel, рваный силуэт, произвольное моделирование или физику жидкости. Базовая форма — острый прямоугольный объём; имитация волокон и износа остаётся эффектом материала.

### Геометрия, UV и данные

Стабильные идентификаторы `front`, `back`, `edge.top`, `edge.right`, `edge.bottom`, `edge.left` независимо от ориентации камеры. Объект центрирован; толщина распределяется симметрично относительно исходной плоскости; вращение камеры не меняет геометрию. UV каждой стороны определены локально; на обратной стороне задан явный режим ориентации. Для торцов P0 — независимые локальные UV каждой грани с единым повтором и размером, швы на углах допустимы и отображаются в документации; непрерывная развёртка периметра — исследование для P1. Проверить перевороты на асимметричных контрольных изображениях, наложение и нормали.

Предлагаемая модель: `geometry: { kind: "rectangle", width, height, thickness, unit }`, `materials: { front, back, edges }`; `edges` хранит общий материал и необязательные будущие переопределения для четырёх граней. Файлы прежнего формата, в котором толщина отсутствует, мигрировать к `thickness: 0` с сохранением сторон; не объявлять новую схему реализованной. При положительной толщине геометрия не должна иметь дублирующихся перекрывающихся поверхностей; проверить winding, depth, прозрачность, размеры и утечки ресурсов при многократном переключении.

Vertex-деформации относятся к P1. Если толщина положительна, фронт, обратная сторона и торцы должны деформироваться согласованно, с совпадением разделённых вершин на швах и корректными нормалями; это отдельный критерий прототипа. До проверки можно заблокировать сочетание эффекта с толщиной и объяснить причину; выпуск P1 не считается готовым, если обе функции по отдельности работают, но их сочетание ломает геометрию.

## Концепция интерфейса

### Структура рабочего экрана

| Зона | Содержание | Что видно сначала |
| --- | --- | --- |
| Верхняя панель | Название проекта, сохранить, открыть, undo/redo, экспорт, состояние автосохранения. | Короткие подписанные действия; состояние и ошибки доступны текстом. |
| Центр | Большой 3D-просмотр, подсветка выбранной области и навигация. | Метки «Лицевая», «Обратная», «Торцы»; кнопки вида спереди/сзади/сбоку и сброса. |
| Левая панель | Вкладки «Материал», «Слои», «Эффекты», «Форма», «Наборы». | Открывается панель текущей задачи, а не список всех параметров GPU. |
| Правая панель | Свойства выбранного объекта: заголовок, область, основные параметры, «Дополнительно». | Только параметры, влияющие на выбор; подсказка объясняет результат обычными словами. |
| Состояние/ошибки | Ненавязчивая строка с понятным действием и подробностями по запросу. | Например, «Изображение не загрузилось. Выберите локальный файл»; данные проекта сохраняются. |

Desktop-first. Панели можно сворачивать и изменять их ширину; при узком окне они переключаются на выдвижные, но предпросмотр и активная задача остаются доступны. Mobile — не заявлен как целевая платформа этапа 1. Обязательны подписи, последовательный таб-фокус, контрастные состояния, управление без drag-and-drop и без единственного ползунка, числовой ввод и видимый фокус.

### Уровни настроек

| Уровень | Вход | Пример для бумаги |
| --- | --- | --- |
| Основной P0 | Карточка выбранного эффекта/слоя | Пожелтение, интенсивность, размер волокон, положение и размер пятна. |
| Дополнительно P0 | Раскрываемый блок внутри той же карточки | Seed, режим смешивания, маска, UV, точные числовые параметры, фильтрация; доступные опции зависят от контекста и устройства. |
| Граф P1 | Явная команда «Открыть граф» | Типизированные узлы и соединения, отдельные стадии vertex/fragment; без обязательного GLSL. |
| Код/диагностика P1 | В графе или отдельной диагностике | Просмотр сгенерированного GLSL и ошибок. Редактирование произвольного GLSL и обещание полного доступа ко всем функциям GPU вне согласованного каталога не входят в первый релиз. |

Предлагаемая схема effect definition содержит `id`, версию, список параметров с типом, диапазоном, умолчанием, единицей, локализованной подписью, подсказкой и `basic`/`advanced`, допустимые стадии и целевые каналы. Этой схемой пользуются и SDK-валидация, и UI; собственное представление проекта остаётся каноническим. При неподдерживаемом в простом режиме графе: сохранять граф как есть, показать «Этот материал изменён в графе» и не делать обратное преобразование автоматически; возврат к слоёвому редактированию предлагает явное действие с предупреждением о возможной потере, которое можно отменить. Если граф остаётся совместимым с карточками, они должны управлять теми же параметрами. Конкретную двустороннюю конвертацию требуется доказать прототипом.

### Сценарии

**1. Бумага с толщиной.** Новый проект → «Бумага» → «Форма» → толщина и размеры → «Вид сбоку» → «Торцы» → цвет/материал. Предпросмотр показывает положительную толщину; значение 0 скрывает торцы, но не удаляет их настройки. Пользователь может вернуться к прежнему значению через undo.

**2. Разные поверхности.** Выбрать «Лицевая» → импорт PNG → «Обратная» → выбрать другую текстуру → вид сзади → при необходимости включить зеркалирование. Заголовок текущей области и подсветка показывают, где появится следующий слой. Переключение стороны не меняет уже настроенный материал другой стороны.

**3. След чашки.** «Эффекты» → «Добавить» → карточка «Кольцо кофе» с миниатюрой → целевая сторона → интерактивная позиция на поверхности или числовые поля → размер, интенсивность и мягкость. «Область» даёт «Вся поверхность», «Форма», «Край поверхности», «Торцы», «Маска из файла» в зависимости от применимости. Манипуляторы не должны перехватывать вращение правой кнопкой. Esc отменяет текущую операцию, undo — завершённую.

**4. Настроить рельеф и шейдер.** Основной режим предлагает «Рельеф» и силу с объяснением влияния света. «Дополнительно» раскрывает карту, оси normal map и фильтрацию. P1 — команда графа, явное разделение стадий и предварительная диагностика ошибок. При сбое компиляции сохраняется последний рабочий результат, отображаются эффект и подробности ошибки; проект и редактируемые параметры не теряются.

**5. Сохранить результат.** Экспорт предлагает «Открыть позже» (архив проекта), «Карты текстур» (отдельно для лицевой, обратной и торцов) и P1 «Пакет для SDK». Предложить разрешение, показать названия карт и занимаемое место приблизительно; если устройство не поддерживает размер, сообщить предел и дать выбрать другое значение. Формат торцов P0: четыре именованных изображения с собственными локальными UV и соответствующими материалами, даже при общем источнике; изображения и manifest связывают каждую грань с UV и размерами. Проверить качество на малой толщине; не обещать бесшовного атласа.

### Состояния и действия

- Пустая панель: объяснение назначения и одна команда добавления. Загрузка: процесс и отмена; ошибка: причина и способ исправить; отсутствующая карта: заглушка и выбор файла, без потери остальных слоёв.
- Изменение пресета: запрос только при замене пользовательских правок с понятными вариантами «Применить поверх», «Заменить» и «Отмена», где комбинация поддерживается; undo обязателен. Переключение выбранной грани не является заменой.
- Вращение правой кнопкой: вращается камера вокруг объекта, объект в проекте не меняется; контекстное меню браузера отключается лишь на viewport. Для клавиатуры/устройств без правой кнопки — подписанные кнопки и клавиатурное управление, колесо — масштаб.
- Визуальные маркеры показывают изменённые дополнительные настройки и скрытые/отключённые слои; цвет никогда не является единственным носителем состояния.

## План проверки удобства

Прежде чем фиксировать визуальный стиль, сделать кликабельный прототип основных задач. Проверить с участниками, не знакомыми с WebGL, и отдельно с опытными авторами материалов; это план, исследования пока не проводились. Предлагаемый первый раунд: 5 новичков и 3 опытных участника, индивидуально, с записью ошибок только с согласия. Участники получают задачи без подсказок:

1. Создать бумагу и сделать её толще, обнаружить торец и изменить его цвет.
2. Разместить разные изображения на двух сторонах, проверить ориентацию обратной стороны.
3. Добавить локальное кофейное кольцо и изменить его размер и положение.
4. Найти дополнительную настройку текстуры и отменить изменение.
5. Сохранить проект, открыть заново и экспортировать карты.

Для каждой задачи записать завершение без помощи, время, неверные действия, моменты непонимания и комментарии. Предварительные пороги: хотя бы 4 из 5 новичков выполняют каждую задачу без подсказок; каждый участник способен найти отмену и понять выбранную сторону; критических потерь данных нет. Это ориентиры для итераций, не статистическое доказательство пригодности. Ошибки с выбором стороны, скрытой толщиной и потерей данных имеют высший приоритет. После исправлений повторить проблемные сценарии с новыми участниками; результаты и точные условия зафиксировать в репозитории.

## Матрица эксперимента Babylon.js и Three.js

На одном и том же устройстве, браузере и фиксированных размерах сцен реализовать одинаковый минимальный SDK-сценарий для обоих кандидатов:

1. Прямоугольник с переходом толщина 0 → положительная → 0; разные материалы двух сторон и общий материал торцов; сохранение параметров.
2. Два независимых изображения, локальные UV, асимметричные контрольные надписи, маска и кольцо кофе; normal и roughness под одинаковым светом.
3. Изменение простого параметра через UI без повторной сборки, изменение структуры эффекта с диагностикой; проверка автоматического построения материала и его восстановление из проекта.
4. Запекание base color/normal/roughness без освещения отдельно для поверхностей и четырёх торцов; сверка ориентации, преобразования цвета и допустимых визуальных погрешностей.
5. Отдельно: vertex-волна на сегментированной объёмной геометрии, согласованность швов и нормалей; импорт/экспорт графа и пользовательского блока; работа offline после загрузки и проверка context loss.

Записать версии и lockfile, размеры production-бандлов (и какие модули загружены), время холодного старта/компиляции, FPS и GPU-память только если её можно надёжно измерить; показать метод и повторения. Функциональные блокеры, успешное восстановление проекта и возможность построить понятный UI важнее одного числа размера. При необходимости пересмотреть выбор в ADR с результатами, ограничениями и известными несопоставимыми моментами. Отдельно проверить, можно ли распространять и загружать зарегистрированные custom blocks без редактора и как извлекаются шейдеры и зависимости; документация сама по себе этого не подтверждает.

## Критерии приёмки P0

- Новичок может завершить пять сценариев выше без знания WebGL; результаты usability-проверки записаны, серьёзные проблемы исправлены или явно согласованы.
- Положительная толщина создаёт видимые реальные торцы, 0 сохраняет двустороннюю плоскость и данные торцов. Отдельные материалы двух основных сторон и общий материал торцов сохраняются при переключении и после открытия проекта.
- Краевая маска и применение к торцам не путаются; грани и UV проверены асимметричными картами, экспорт четырёх карт торцов и их соответствие UV проверен на повторном импорте.
- Настройки разделены на основные и дополнительные, UI сообщает выбранную область, позволяет отменить изменения и не теряет данные при ошибках. Поведение проверено клавиатурой и при узком desktop-окне.
- Приёмо-сдаточные проверки воспроизведения, цветового пространства, CORS, потери контекста, GPU-ресурсов и экспорта из основного исследования остаются обязательными.
